# StemForge — Wayfinder Map

**Type:** map
**Status:** complete

## Destination

A handoff-ready, decision-complete route to **StemForge v0.1.0**: a runnable, local-first NiceGUI desktop app for Linux and Windows that loads local audio or a YouTube URL, previews playback, shifts pitch in semitones with tempo preserved, separates vocals/instrumental locally with Demucs `htdemucs`, and exports through native dialogs — distributable as a Linux AppImage/tar.gz and a Windows portable ZIP/Inno Setup installer.

**This map ends at the handoff. Implementation and scaffolding are a separate effort** (see Out of scope).

## Notes

**Domain:** local-first desktop audio utility for musicians, singers, and creators. No accounts, cloud processing, telemetry, or external APIs. See `GLOSSARY.md`.

**Standing decisions (settled during charting):**

- **License:** GPL-3.0-only for StemForge; the best-quality GPL-compatible audio stack is allowed.
- **Separation:** Demucs `htdemucs`, CPU-first with optional GPU. Four stems are generated; Vocals and Instrumental are the primary UI outputs, with drums/bass/other expandable. The 84 MB weights are downloaded on first use, never bundled (licence unresolved; ADR 0009).
- **Workspace:** multi-track, session-scoped. No persistent project library in v0.1.0; a recent-files list only.
- **Pitch:** non-destructive. A per-track integer semitone setting (±12), an explicit render action, and A/B playback between original and shifted. Pitch and separation are independent artifacts in v0.1.0, with the recommended pipeline order separation → pitch per stem.
- **Audio:** 32-bit float WAV is the canonical internal format; preview uses a cached webview-safe MP3; export offers WAV 24-bit, FLAC, and MP3 320.
- **Distribution:** Linux AppImage + tar.gz (x86_64, glibc 2.35+); Windows portable ZIP + Inno Setup (Windows 10/11 x64, WebView2 with bootstrapper fallback). GitHub Actions builds both.
- **v0.1.0 surface:** drag-and-drop load, YouTube URL import, track list, playback, semitone stepper + render, separation with progress/cancel, per-stem playback, export, native dialogs. Deferred: waveform, stem mixer, batch export, library, shortcuts, themes.

**Skills every session should consult:** `grilling` + `domain-modeling` for decision tickets; `research` for AFK research; `prototype` for the UI and icon tickets; `codebase-design` for module boundaries.

**Research artifacts:** `.scratch/stemforge/research/` — one report per research ticket, linked from the ticket.

**Licensing artifacts:** `.scratch/stemforge/licensing/` — the compliance inventory and the drafted shipped notice; ADR 0009 records the weights policy.

**ADRs:** record hard-to-reverse, surprising trade-offs under `docs/adr/` as tickets resolve.

**Blocking:** local-markdown convention. A ticket is unblocked when every ticket in its `Blocked by:` line is `resolved`. The frontier is open, unblocked, unclaimed tickets, lowest number first.

**Handoff:** [`HANDOFF.md`](../../HANDOFF.md) — produced by [v0.1.0 scope, acceptance criteria, and roadmap](issues/15-v0.1.0-scope-acceptance-and-roadmap.md) and the implementation effort's entry point. The map remains the decision record; where they disagree, the ticket wins. All map tickets are resolved: [App icon art](issues/17-app-icon-art.md) chose A — Badge and delivered the assets to `src/stemforge/assets/`; the map is complete and implementation is the remaining effort.

## Decisions so far

- [Desktop shell and audio-preview feasibility](issues/01-desktop-shell-and-audio-preview.md): keep NiceGUI native mode + pywebview; GTK/WebKitGTK on Linux, assert WebView2 on Windows; serve cached MP3 previews over NiceGUI's range-capable HTTP route (no `file://`); wrap native dialogs with strict filter grammar and save-extension normalization. Linux packaging is the top risk: research recommends tar.gz primary and AppImage only as a thin host-dependent wrapper; final call in ticket 10.
- [Separation engine and invocation](issues/02-separation-engine.md): `demucs==4.1.0` + `htdemucs`, CPU-only torch 2.15, CPython 3.13, subprocess worker with JSONL progress; pin numpy explicitly (release blocker); 84 MB weights have an unresolved licence (resolved in 13: not bundled; first-run download); PyInstaller onedir ~881 MB on disk / ~197 MB compressed.
- [Pitch-shift engine and media pipeline](issues/03-pitch-shift-and-media-pipeline.md): Rubber Band 4.0.0 CLI in R3/offline/formant mode; FFmpeg/ffprobe 9.0.2 GPLv3 static binaries; canonical 44.1 kHz f32 WAV, MP3 192 preview, WAV 24/FLAC 24/MP3 320 export; yt-dlp Python API + Deno pinned; separate before pitch per stem; all components GPL-3.0-compatible.
- [Packaging toolchain and CI feasibility](issues/04-packaging-and-ci.md): PyInstaller 6.22 onedir with native per-OS builds; Linux tar.gz primary and opt-in thin AppImage (host WebKitGTK/GStreamer, no bundling); Windows ZIP + per-user Inno Setup with WebView2 bootstrapper; `freeze_support()`; custom spec reuses nicegui-pack's NiceGUI-as-data trick (the CLI cannot take a spec); release assets not Actions artifacts; do not bundle Demucs weights (unresolved licence) — first-run download; Windows bundles only on Windows runners.
- [Audio pipeline and format policy](issues/05-audio-pipeline-and-format-policy.md): canonical stereo 44.1 kHz f32 WAV at import (mono→dual-mono, >2ch downmix, 48k downsampled); Separation reads only the original, Pitch reads the original or Stems and never feeds Separation; Instrumental stored as the sum of non-vocal stems, shifted Instrumental summed from shifted stems; preview MP3 192 over GET+Range only (no HEAD, 416 on suffix/multi); export WAV 24 / FLAC 24 / MP3 320 from the master with record-driven tags, cover in MP3/FLAC, no normalization; one shared static gain per artifact set only when a peak exceeds 0 dBFS, applied at preview/export, never baked into masters; R3+formant only; content-hash artifact identities, staging + atomic promotion, persistent LRU cache.
- [Application architecture and module boundaries](issues/06-app-architecture-and-module-boundaries.md): one `src/stemforge` package with an enforced one-way dependency rule (`ui → application → jobs/pipeline/artifacts → engines → platform`); a single `JobRunner` thread with one active FIFO Job, dedupe, snapshot polling and process-group cancel; Separation alone crosses a Python process boundary (`--worker separation` reusing the frozen binary), while Pitch, FFmpeg and yt-dlp are adapters; immutable Source/Track/Artifact state in one app-wide Workspace, settings in JSON, never browser storage; artifacts indexed only by filesystem manifests; localhost-only HTTP with one cache-rooted `/media` route and no auth; Python 3.13, one `uv.lock`, CPU torch, explicit `numpy`; coded `StemForgeError` taxonomy and per-Job logs. ADRs 0003–0005; glossary gains *Artifact set* and *Render*.
- [Workspace storage and lifecycle](issues/07-workspace-storage-and-lifecycle.md): per-user roots (`~/.local/share/stemforge` data + models, `~/.config/stemforge`, `~/.cache/stemforge` 8 GiB LRU cache, `~/.local/state/stemforge/log`; `%LOCALAPPDATA%\StemForge` plus `Cache`/`Logs`), with a `STEMFORGE_HOME` override, a single-instance lock, and a full startup sweep. The cache outlives the in-memory Workspace; only explicit Remove (with confirmation), LRU eviction, or Clear cache delete completed artifacts. Model weights are pinned by HF revision + SHA-256 and re-verified before every Separation; recent files (10) and settings live in JSON; logs are 3 × 2 MiB plus 20 job logs / 7 days. No per-session directory. ADR 0006; glossary gains *Cache*.
- [UI workflow and layout prototype](issues/08-ui-workflow-and-layout.md): variant A (rail & detail) won over B's tile rack and C's pipeline lanes — 292 px rail with tracks/recent/cache, per-track signal path, transport, Pitch and Separation cards, one Outputs list; renders are immutable version tabs per (semitones, scope) with `master`/`stems` suffixes when both exist, A/B flips Original↔newest, one player at a time; inline model gate with auto-resubmit; format sheet → native save dialog → atomic write; 1024×700 minimum; no close prompt and no close veto.
- [YouTube import behavior](issues/09-youtube-import-behavior.md): public, non-age-gated videos only, one per import, ≤15 min; no cookies/accounts, no PO-token provider, pinned `yt-dlp 2026.10.26` / EJS 0.8.0 / Deno 2.9.8 with no runtime updater (ADR 0007). Reachable shapes are `watch`/`youtu.be`/`shorts`/`embed`/`live`/`m.`/`music.`/scheme-less/bare ID; playlists, channels, searches, and other hosts fail as field errors. One `import_youtube` Job: resolve (metadata-only) → 5 s pacing → download (hooks) → decode → preview → commit; cancellation raises through a progress hook; errors split into `import.youtube_*` / `import.network` with stable messages. `source_id` is `yt-<id>`; cache hits never touch the network, and Remove + re-import is the only refresh. One-time consent modal, persistent disclaimer line, and a "YouTube import" toggle; "Clear YouTube cache" deletes only `<cache>/yt-dlp/`. Corrects ticket 07's import estimate to 24 MB/min.
- [Performance and resource envelope](issues/12-performance-and-resource-envelope.md): Separation RTF 0.57–0.72 measured / 1.5 conservative, ~278 MiB/min + ~355 MiB RSS; 8-minute blocks with a 1 s crossfade keep peak ~2.7 GiB; 30-minute local cap (`import.too_long`, YouTube stays 15), 8 GiB cache fits one full 30-minute workflow, 8 GB RAM / 20 GB disk minimum, 16 GB / SSD recommended. Pitch 4 min is 48 s (+12) / 23 s (−12); decode, preview, and exports are seconds. Frozen onedir 916 MB / 2,940 files, 199 MB tar.zst, 1.9 s imports-ready, 168 MB trim; ~1.0–1.05 GB with ffmpeg/Deno after trim. ADR 0008; Windows/GPU and full-app startup unmeasured.
- [Licensing and attribution compliance](issues/13-licensing-and-attribution-compliance.md): StemForge is GPL-3.0-only; the `htdemucs` weights are never bundled or mirrored (unresolved licence, likely non-commercial) — first-run download from HF at pinned revision + SHA-256 behind an explicit consent gate (ADR 0009), so no offline pack in v0.1.0. One FFmpeg provenance for both OSes: BtbN GPL static `n9.0.2-57-gd838f9f9ae` (pinned SHAs), exact configure line captured from `-buildconf`; gyan rejected (no published configure line, no SoXR), LGPL rejected (loses rubberband). Rubber Band 4.0.0 and libsndfile 1.2.2 are built from source (builtin FFT/resampler; shared WAV-only libsndfile) rather than trusting the official zip. yt-dlp wheel (Unlicense) + EJS + Deno, not the GPLv3+ binary. `THIRD_PARTY_NOTICES.md`/`LICENSES/`/`SOURCE_OFFER.md` are generated from `uv.lock` + dist-info + curated native/frontend manifests and CI-verified; GPLv3 §6(d) source assets plus a 3-year written offer. `torchaudio` is excluded (not on the Separator path); PyTorch/NumPy GCC runtime and NiceGUI's Quasar/Vue/fonts need curated notices. About modal supplies licence, notices, source, and licences folder. Glossary gains *Corresponding Source*, *Model weights*, *Source offer*, and *Third-party notices*.
- [Packaging and distribution plan](issues/10-packaging-and-distribution-plan.md): PyInstaller 6.22.3 onedir on CPython 3.13, native `ubuntu-22.04`/`windows-2022` builds, one tree with `_internal/` plus a `vendor/` tree beside it for FFmpeg/ffprobe/Deno/Rubber Band/libsndfile (ADR 0010); Linux tar.gz canonical + tar.zst + a thin zstd AppImage that requires host GTK/WebKitGTK 2.44+/GStreamer and falls back to the browser via `run.sh`/`--preflight` (ADR 0011); Windows portable ZIP + per-user Inno (`MinVersion=10.0.19045`, WebView2 bootstrapper, `edgechromium` asserted), Win 11 primary / Win 10 22H2+ESU best-effort; unsigned v0.1.0 + `SHA256SUMS` + SmartScreen note; version `0.1.0` from `stemforge.__version__`, tags `v0.1.0`, every URL from `packaging/release.toml` with a CI placeholder gate (owner settled in 18); release assets go straight to a draft GitHub Release from a tag-triggered `release.yml` (`prepare`/`linux`/`windows`/`sources`/`publish`), with a Linux-only PR frozen smoke owned by 11; CPU-only confirmed, weights first-run, frozen `--self-test`/`--smoke-test`/`--smoke-separation` gates (1 s separation <60 s, <2 GB), budget ~1.15 GB onedir and 20/35-minute builds; icon asset contract fixed, final art delivered in 17. Glossary gains *Bundle*, *Portable build*, *Thin AppImage*, and *Vendor binary*.
- [Repository home and release URLs](issues/18-repository-home-and-release-urls.md): GitHub, `https://github.com/alexmarincu/stemforge`, public from the first commit; `repo_url`/`releases_url`/`source_offer_contact` fixed in `packaging/release.toml`, human release page `/releases/tag/v<ver>`, asset downloads `/releases/download/v<ver>/<name>`; tags immutable after publication; created 2026-11-15 and still empty — the first commit lands when the map closes, at implementation start. The three-year source offer and the notices now have a real home.
- [Testing and CI strategy](issues/11-testing-and-ci-strategy.md): four layers (unit/integration/UI + script-driven frozen smoke) with generated audio fixtures and structural/DSP assertions, no byte hashes; PR CI is lint, unit on Linux+Windows, real-binary integration on both, UI, licensing, coverage, and one Linux frozen build <15 min with no weights; the real 1 s Demucs separation (<60 s, <2 GB), AppImage extraction, and both frozen bundles run nightly and at release; PR catches the missing-`numpy` blocker with a `demucs.api` import only; coverage 85% core/70% overall, mypy strict, import-linter, shellcheck, PowerShell Error severity; release gated by `release.yml`, `verify-release.sh`, both frozen separations, 10's budgets, and the manual `docs/qa/release-checklist.md`; published tags/assets are immutable, so failures are fixed forward.
- [Failure modes and recovery](issues/14-failure-modes-and-recovery.md): one owner, one code, one sentence, one action per failure. Fatal preflight (platform, window runtime, damaged Bundle, unwritable roots) ends in a native message box with the fix line and exit 3/5/6/7/8 before the window; a missing GStreamer preview stack only degrades playback (banner, transport disabled, separation/pitch/export still work); low RAM/disk warn. No automatic retries — manual Retry re-submits the identical spec, and the one automatic action is the Separation re-submit after a successful model install. Plain headline with code/log behind Details; unclassified exceptions become `internal.unexpected`. Crash recovery sweeps staging/partials, never resumes, and finished artifacts are deleted only by Remove, LRU, or Clear cache — never to escape a disk-full, which offers those actions instead. Cancellation deletes the job's staging and destination `.partial`; a commit is not interruptible; one Job means no per-track locks, Remove cancels that track's jobs first, close cancels and exits without a prompt. Diagnostics are a local copy-only report (versions, paths, settings, log tails), resolving the map's diagnostics fog. ADR 0012; glossary gains *Preflight*, *Degraded mode*, *Diagnostics report*, *Partial*.
- [v0.1.0 scope, acceptance criteria, and roadmap](issues/15-v0.1.0-scope-acceptance-and-roadmap.md): the handoff is root [`HANDOFF.md`](../../HANDOFF.md) and is the implementation entry point — a compact index, not a second decision store. v0.1.0 is frozen exactly as charted (the final icon art is part of v0.1.0 and is now delivered); acceptance is two-part, a user-visible Linux/Windows matrix plus ticket 11's existing automated gates with no new thresholds; eight phases (scaffold with a thin frozen-build spine, load/preview, pitch, separation, YouTube, export, packaging, hardening) each exit on a demo + its gate; source-run and both-bundle definitions of done are fixed; Windows figures stay measured-in-hardening and disclosed, not gated; no v0.2.0 theme — the post-v0.1.0 backlog is ordered waveform → mixer → library → batch → GPU pack; release GO requires licence sign-off, both bundles' smoke/matrices, no weights, budgets met, and complete error copy, with NO-GO on licence, Windows backend, or budget overrun. [17](issues/17-app-icon-art.md) was the only open map ticket at handoff and is now resolved — it chose the final mark and produced the assets, not a roadmap change.

## Out of scope

- **Implementation and scaffolding** — this map ends at a handoff-ready plan; building the repo is a separate effort.
- **Building or signing Windows bundles on Linux** — Windows artifacts are built on Windows/CI runners.
- **macOS, ARM, mobile, and 32-bit builds.**
- **Persistent project library, waveform display, stem mixer (mute/solo/volume), batch export, keyboard shortcuts, themes** — deferred post-v0.1.0.
- **Post-v0.1.0 audio niceties** — draft/low-quality pitch render mode, formant toggle, original-file passthrough export ("Save original"), YouTube thumbnail embedding.
- **Bundled or offline `htdemucs` weights** — ruled out until the weights' licence is resolved; v0.1.0 downloads them from Hugging Face on first use (ADR 0009).
- **Project-built audio-only FFmpeg** — a post-v0.1.0 bundle/source-offer optimization; v0.1.0 uses the pinned BtbN GPL static build.
- **Real-time pitch shifting, VST/plugin hosting, karaoke/MIDI features.**
- **Cloud sync, accounts, telemetry, auto-update, i18n.**
- **Code signing and SmartScreen reputation in v0.1.0** — v0.1.0 ships unsigned with published `SHA256SUMS`; the signing hooks exist, but acquiring a certificate and building reputation is a post-v0.1.0 decision.
- **Windows performance and startup measurement ([ticket 16](issues/16-windows-performance-verification.md))** — it needs a built, frozen Windows bundle, so the measurement belongs to the implementation effort. The handoff carries "Windows figures unmeasured" as a disclosed limitation; ticket 16's question is the recipe.
- **Distro packages (deb/rpm/Flatpak) in v0.1.0.**
