# 09 — YouTube import behavior

**Type:** grilling
**Status:** resolved
**Blocked by:** 03, 06

## Question

Define the YouTube import contract:

- Accepted URL forms; playlist/channel rejection; maximum duration; audio-only format preference; ffmpeg extraction.
- Pins: research 03 recommends `yt-dlp==2026.10.26`, `yt-dlp-ejs==0.8.0`, `deno==2.9.8`, the Python API, `format: bestaudio/best`, `noplaylist: True`, keeping the native file and decoding to canonical WAV; cache by video ID.
- Limitations: age-restricted/private content needs opt-in cookies; PO tokens cannot be generated by yt-dlp; YouTube's ToS restricts downloading; surface a clear disclaimer and actionable errors.
- Progress reporting for download and extraction; cancellation; retry.
- Cache keyed by video ID? Location; retention; reuse across Tracks.
- Failure states: unavailable, private, age-restricted, live, DRM, network loss, and disk full; user-facing messages.
- Metadata (title, uploader, duration, thumbnail) and filename sanitization.
- Legal/ToS notice text and placement; offline behavior.
- yt-dlp update policy (pinned version vs bundled updater).

The answer must be implementable without further product decisions.

## Answer

The YouTube import contract, closed. Upstream ownership is unchanged: ticket 05 owns the source and artifact layout, 06 the Job model and error base, 07 the roots/cache/retention, 08 the UI placement. This ticket fixes what is accepted, what runs, what the user sees, and how long the feature lives.

**Correction to 07 §8:** its "import YouTube" row budgets 1.5 MB/min for native + canonical + preview. Canonical alone is 21.2 MB/min (§8's own figure), preview is 1.44 MB/min, and native Opus/AAC is ~1.5 MB/min — use **24 MB/min**, superseding that row.

### 1. Accepted inputs

One public, non-age-gated video per import. Public URLs; no account, cookies, playlists, channels, or other sites.

| Input | Accepted as |
|---|---|
| `youtube.com/watch?v=<id>` (+ any params, incl. `list=`) | video `<id>` |
| `youtu.be/<id>` (+ params) | video `<id>` |
| `youtube.com/shorts/<id>`, `/embed/<id>`, `/live/<id>` | video `<id>` |
| hosts `www.`, `m.`, `music.` | as above |
| scheme-less paste (`youtu.be/…`, `youtube.com/watch?…`) | prepend `https://` |
| bare `[A-Za-z0-9_-]{11}` | video ID |

Shape validation is **synchronous at submit**, before any Job: trim, prepend scheme if absent, parse host + path. Refused immediately, with the field-level codes below: playlist-only (`/playlist?list=`), channel/handle (`/@name`, `/channel/`, `/c/`, `/user/`), search (`/results?`), any non-YouTube host, and anything unparseable. A `watch?v=X&list=Y` URL is the single video `X`; `noplaylist: True` guarantees the list is never followed.

`origin` is canonicalised to `https://www.youtube.com/watch?v=<id>` everywhere (source.json, recent files, `comment` tag). The app-side ID is a cache pre-check only; after resolve, **yt-dlp's `info["id"]` is authoritative** (it follows redirects and normalises Shorts), and a disagreement is stored, not treated as an error.

### 2. Limits and refusals

- **Duration cap 15:00**, checked at resolve. Unknown duration is allowed through and re-checked after ffprobe; over-cap then aborts and deletes staging.
- **Live, upcoming, and premieres refused** (`is_live`, `live_status` in `is_live`/`is_upcoming`); a completed `was_live` stream is allowed.
- **Age-gated refused**: `age_limit > 0`, or the extractor's age error. v0.1.0 has no cookie path, no account, and no keyring access.
- **Private, members-only, premium, region-locked, removed, and DRM-protected** refused as one unavailable class.
- **Playlists refused even when the URL looked like a video**: after resolve, `_type` must be `video`; anything else is `import.youtube_playlist`. `noplaylist: True` is still set as defence in depth.
- **No PO-token provider** is bundled and none is planned. Bot-check/PO-token failures classify as rate-limited when the message names a bot check or HTTP 429, otherwise as extractor-outdated. The remedy is always wait-and-retry or update the app.

### 3. Job, stages, progress, cancellation

One Job, kind `import_youtube`, on the single JobRunner thread (06). Submit is synchronous-validated first; the Job then runs:

| Stage | Weight | Signal | Stage text |
|---|---|---|---|
| resolve | 0–5% | `extract_info(url, download=False)` | `Checking video` |
| pacing (conditional) | at 5% | 5 s spacing since the last YouTube download | `Waiting for YouTube · 3 s` |
| download | 5–75% | `progress_hooks` bytes + speed | `Downloading audio · 12.3 of 45.1 MB · 2.1 MB/s` |
| decode/canonicalise | 75–90% | FFmpeg `-progress` (05) | `Decoding audio` |
| preview | 90–96% | FFmpeg `-progress` | `Encoding preview` |
| validate/commit | 96–100% | ffprobe + hash + atomic rename | `Finishing` |

- Resolve is a second extraction; the extra player request is accepted so an over-long, live, or age-gated video is refused before bandwidth is spent.
- Progress is throttled to 4 Hz; the adapter calls `progress()` with the current fraction at least every 5 s while blocked (resolve, pacing, a silent socket) so the 30 s stall warning never fires spuriously. The watchdog stays a warning, never a kill (06).
- **Cancellation:** the progress hook raises `yt_dlp.utils.DownloadCancelled`, which propagates out of `extract_info` (verified in 2026.10.26: `_hook_progress` has no try/except, the HTTP downloader's bare `except:` re-raises after closing the stream, and `_handle_extraction_exceptions` re-raises with `ignoreerrors: False`). The adapter converts it to `JobCancelled`. Between-stage checks cover resolve and pacing. The Job's staging directory — native file, `.part` fragments, partial canonical/preview — is deleted by the JobRunner rule. No yt-dlp subprocess: in-process stays per 06, and a crash kills only the runner thread's Job.
- **Dedupe/one Job:** the UI disables the field while any Job runs (08); the service returns the running `import_youtube` Job id instead of submitting a second one, whatever the URL.
- **Cancel is not failure** and writes no error; Retry re-submits a fresh Job.

### 4. yt-dlp invocation

Lazy `from yt_dlp import YoutubeDL` inside the adapter (startup and frozen-build rules, 06 §11). Options:

```python
{
    "format": "bestaudio/best",
    "noplaylist": True,
    "outtmpl": {"default": "%(id)s.%(ext)s"},
    "paths": {"home": str(staging)},
    "cachedir": str(cache / "yt-dlp"),
    "windowsfilenames": True,
    "trim_file_name": 120,
    "quiet": True,
    "no_warnings": False,          # warnings go to the Job log
    "noprogress": True,
    "ignoreerrors": False,
    "logger": adapter_logger,      # Job log only
    "progress_hooks": [adapter_hook],
    "retries": 3,
    "fragment_retries": 3,
    "extractor_retries": 3,
    "socket_timeout": 20,
    "progress_delta": 0.5,
    "warn_when_outdated": False,
    "ffmpeg_location": str(binaries.ffmpeg().parent),
    "js_runtimes": {"deno": {"path": str(binaries.deno())}},
    "postprocessors": [],
}
```

- No `FFmpegExtractAudio`, no metadata/thumbnail postprocessors: the native file is kept and decoded by our FFmpeg pipeline (05).
- `DENO_DIR=<cache>/deno` is set by `environment.py` (07); the yt-dlp cache lives at `<cache>/yt-dlp` and is the only thing "Clear YouTube cache" deletes.
- No `cookiefile`/`cookiesfrombrowser` and no `proxy` option; yt-dlp's default networking applies. YouTube import is the only network path in the app; no telemetry, no URL reporting, no proxying.
- The native file is the one yt-dlp reports in `requested_downloads[0]["filepath"]`, extension preserved; it is probed, hashed, and moved to `sources/yt-<id>/native.<ext>`. Retained for the life of the cache entry (07 §3).
- If the selected format has no audio stream (`acodec == "none"`), fail `import.no_audio_stream` before decoding.

### 5. Cache reuse, identity, commit

`source_id = "yt-<video_id>"` (05). On submit:

1. `sources/yt-<id>/source.json` valid **and** canonical ffprobe-valid → open the Track immediately, **no network**. Offline cache hits work.
2. Canonical missing/invalid but native valid → re-decode and re-encode preview locally, no network.
3. Native file fails its recorded SHA-256, or both files are unusable → delete the subtree and download again.
4. No entry → download into `staging/<job_id>/`, validate (ffprobe duration/codec/rate/channels, ffmpeg decode, peak), write `source.json` last, promote with one atomic directory rename to `sources/yt-<id>/`, touch `.used` (07 §2).

No periodic revalidation, no background refresh, no "force re-download". The video's audio may change upstream; the cache stays as imported until the user removes the Track (which deletes the subtree, 07 §3) and imports again. That is the documented escape hatch, not a bug.

`source.json` carries the 06 §12 fields plus YouTube specifics: `origin_kind: "youtube"`, `origin_url`, `video_id`, `native_sha256`, `native_bytes`, `format_id`, `extractor`, `extractor_version`, and the tool trio versions. Stems/renders reference the source as usual.

**Disk:** estimate **24 MB/min** (native ~1.5 + canonical 21.2 + preview 1.44), ×1.2, against 07 §8's `max(1 GiB, estimate × 1.5)` floor on the cache volume — checked before download and again before promotion.

### 6. Metadata and names

| Record field | Source |
|---|---|
| `title` | `info["title"]`, NFC, whitespace-collapsed, ≤200 chars; fallback `YouTube <id>` |
| `artist` | `info["uploader"]`, fallback `channel` |
| `date` | `info["upload_date"]`, `YYYYMMDD` → `YYYY-MM-DD` |
| `comment` | canonical URL |
| `source_url` | canonical URL |
| `source_id` | `yt-<id>` |
| `duration`, `sample_rate`, `channels` | canonical WAV after probe |
| `album`, `album_artist`, `track`, `disc`, `genre`, `composer`, `copyright` | empty |
| `cover_path` | null — YouTube thumbnails are not downloaded or embedded |

Track display name is `title`; the rail shows the video icon and `YouTube`. Export suggestions use 05 §7's Windows-safe sanitisation (reserved names, trailing dots/spaces, 120-char base) and never the raw title as a path.

### 7. Consent, toggle, and exact strings

- Under the empty-state field, 11 px, always visible (08 §2):
  *"Only import content you have the right to use. YouTube's Terms of Service prohibit downloading."*
- On the **first** YouTube import, before the Job is submitted, a consent modal:
  - Title: *Import from YouTube*
  - Body: *StemForge downloads audio with yt-dlp, entirely on this machine. YouTube's Terms of Service prohibit downloading except where the law permits, and downloading may infringe copyright. Only continue if you have the right to use this content.*
  - Buttons: `Cancel` / `I have the right to use this content`
  - Persisted as `youtube_notice_acknowledged: true` in `<config>/settings.json`; never shown again, never shown at startup.
- Settings & About → Behaviour gains **YouTube import** (default `youtube_enabled: true`). Off: the empty-state YouTube row is hidden, and recent YouTube entries show a "YouTube import is off" state with no action. Local import, playback, pitch, separation, and export are unaffected.
- Settings & About → Storage gains **Clear YouTube cache**: deletes `<cache>/yt-dlp/` only (shows its size), never `sources/`, `renders/`, recent files, or Deno.
- About gains a paragraph: *YouTube import uses yt-dlp, yt-dlp-ejs, and Deno locally. It needs no account, sends no telemetry, and uses no proxy. Age-restricted and private videos are not supported in this version.* External URLs appear as selectable text; v0.1.0 opens no external browser from the app.

### 8. Errors

Field-level (`Import` stays responsive, no Job):

| Code | Trigger | Message |
|---|---|---|
| `import.youtube_url_invalid` | unparseable / no video id | That doesn't look like a YouTube link. |
| `import.youtube_playlist` | playlist/channel/search URL, or resolve returns non-video | That's a playlist or channel. Paste a single video link. |
| `import.unsupported_source` | non-YouTube host | Only YouTube video links are supported. |

Job-level (toast + rail/empty state, 08 §11):

| Code | Trigger | Message | Retry |
|---|---|---|---|
| `import.youtube_too_long` | duration > 900 s | This video is 24:10 — longer than the 15-minute limit. | no |
| `import.youtube_live` | live / upcoming | Live and upcoming streams can't be imported. | no |
| `import.youtube_age_restricted` | age gate | This video is age-restricted. StemForge doesn't sign in to YouTube. | no |
| `import.youtube_unavailable` | private/removed/members/geo/DRM | This video isn't available. It may be private, removed, region-locked, or members-only. | no |
| `import.youtube_rate_limited` | 429, bot check, "try again later" | YouTube is limiting downloads from this machine. Wait a few minutes, then retry. | yes |
| `import.youtube_extractor_outdated` | extraction/JS/format failure | YouTube changed and this StemForge version can't read the video. Update StemForge. | no |
| `import.network` | DNS/timeout/connection | No connection. Check your network and retry. | yes |
| `import.download_failed` | anything else, mid-transfer | The download failed. Retry, or open the job log for details. | yes |
| `import.no_audio_stream` | no audio format | This video has no audio track. | no |

One mapper owns classification, in this order: unavailable → age → live → rate-limit/bot → extractor/JS → network → `download_failed`. It reads exception classes and message patterns; unmatched text never reaches the UI, only the Job log. `decode.failed` and `storage.*` keep their existing owners and messages (14). A cancelled Job is not an error.

### 9. Version policy

- Pin `yt-dlp==2026.10.26`, `yt-dlp-ejs==0.8.0`, `deno==2.9.8` in `uv.lock`; packaging bundles all three.
- **No runtime updater, no nightly channel, no update check.** The wheel lives inside the frozen bundle; updating it would write into `_internal` and execute code fetched at runtime.
- About shows all three versions. Extraction breakage is fixed by shipping a new app release with a new pin; `import.youtube_extractor_outdated` says exactly that. `warn_when_outdated` stays off so yt-dlp's own 90-day notice never reaches the UI.
- Revisit only with an out-of-process adapter and a signed update channel (see ADR 0007).

### 10. Accepted v0.1.0 limitations

- Public, non-age-gated videos only; no cookies, accounts, or PO-token provider.
- No playlists, channels, searches, or non-YouTube sites; one video per import.
- 15-minute cap; no re-download/refresh action; the cache is the artifact of record.
- No thumbnails or covers for YouTube sources.
- YouTube changes can break import until an app update ships.
- yt-dlp runs in-process; a hard crash fails the Job, not the app.
- Import is the only network path and can be disabled; no proxy UI.
